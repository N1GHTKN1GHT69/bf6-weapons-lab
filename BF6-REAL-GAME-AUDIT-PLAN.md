# BF6 Weapons Lab — real-game audit plan

Generated by `scripts/build-real-game-audit-plan.mjs` from live repository data.
Every CURRENT LAB CLAIM below is read out of the combat cache, the class audits, the source
capture or the REDSEC model at generation time — none is transcribed by hand, because a stale
figure in an audit plan sends someone to verify a number the Lab no longer makes.

**Lab state at generation:** LIVE 1.4.2.5 · DATA 1.4.2.0 · COMBAT 1.4.1.5

## How to use this

The game is the arbiter. Where the game and the Lab disagree, the Lab is wrong.

Work **strictly in tier order**. Tier 1 tests establish rules that dozens of weapons inherit —
a single Tier 1 failure invalidates far more than a Tier 4 failure, so Tier 1 has the highest
information per trigger pull. But do **not** treat Tier 2 as redundant once Tier 1 passes:
Tier 1 establishes a rule from one caliber, and Tier 2 asks whether it actually generalises.
Assuming generalisation without testing it is how a shared-rule model silently goes wrong.

Record the observed value for every test, including passes. A pass is evidence and belongs
in the record; only recording failures makes the coverage figure unauditable.

| Tier | Tests | What a failure invalidates |
| --- | ---: | --- |
| 1 — mechanism | 12 | a rule applied across dozens of weapons |
| 2 — class representative | 7 | one whole weapon class |
| 3 — edge case | 22 | a specific weapon, value or unresolved mechanic |
| 4 — roster confirmation | 43 | one weapon |
| **total** | **84** | |

## Start here — the three tests with the highest information value

1. **T1-001 shot interval.** If TTK is not `(BTK-1) x 60000/RPM`, every ranking in the app is
   built on the wrong base. Cheapest possible test, largest possible blast radius.
2. **T1-002 damage breakpoints.** The app promises answers at an exact metre. If drop-off is
   banded or interpolated rather than stepped, that promise is false everywhere.
3. **The REDSEC spillover test** (Tier 1, and fully designed in
   `reports/overnight/redsec-experiments.json`). It is the only measured decision-relevant
   uncertainty in the whole project, and it is a binary test: fire exactly the model-B shot
   count and see whether the target dies.

## What this plan deliberately does NOT ask you to do

- **Confirm a sub-0.1% ranking order.** Six such pairs are listed in Tier 3, and each asks you
  to verify the INPUTS instead. No amount of play separates two weapons the model itself
  separates by 0.02%, and pretending otherwise would manufacture a result.
- **Verify values with no published source by comparison to a source.** Damage curves have no
  current publisher; the game is the only arbiter available, which is why they are tested
  directly rather than reconciled.
- **Test the BALANCED weighting.** It is a product preference, not a game mechanic. The game
  cannot tell you whether 55/45 is the right trade-off — only whether its inputs are right.
